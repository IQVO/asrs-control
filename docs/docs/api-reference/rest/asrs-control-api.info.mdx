The subsystem-controller interface of **asrs-control** (WCS tier, Generic; ADR 0001), called by
material-flow-control (WCS context map relationship 5). A store or retrieve is accepted or refused at once
(`202` or `422`); its progress is reported only by events on `warehouse.asrs-control.events`
(ContainerStored, ContainerPresentedAtPort, StorageJobFailed). Rack positions never appear here.

**Idempotency.** Every POST requires `Idempotency-Key` (1-128 characters). The first request executes; a
retry with the same key and body returns the stored answer with `Idempotency-Replayed: true`; the same key
with another body is `409 idempotency-key-reused`. Only 2xx and FINAL refusals are stored (24 hours):
`bad-request`, `invalid-parameter`, `asrs-not-found`, `storage-job-not-found`, `unknown-port`,
`wrong-port-kind`. RETRYABLE refusals release the key, so a retry under the same key executes again:
`unknown-container`, `container-busy`, `container-already-stored`, `storage-full`, `aisle-unavailable`,
`port-unreachable`, `port-not-presenting`, `job-not-cancellable`, `job-ended`.

**Errors** are RFC 9457 `application/problem+json` with a stable `code`. No authentication (fleet rule).
